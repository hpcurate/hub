## What was done

### Remembering the data — request 1

Two answers, because the request asked for either and both are worth having.

**The update itself.** v0.3.0 moved the extension's storage from `localStorage`
to `chrome.storage.local`, and a board that had channels in the old place opened
empty. That is not an acceptable way for an update to behave. The store now
reads the old place once, on a cold start, and carries it over — and only ever
when the new store is empty, so it can never overwrite anything or merge twice.
Ordinary updates were never the problem: `chrome.storage.local` survives
reloading an unpacked folder.

**A file.** Export writes one JSON file with every channel, category and
setting, stamped with a `kind` that import checks before it replaces anything —
a JSON file that happens to have the right-looking fields is not the same as a
file this wrote. Import is forgiving about what is *inside* (an older export
missing a field is still worth restoring) and unforgiving about what the file
is. It says what it restored, or why it would not.

This also closes the one gap that stays real: the board off disk and the board
inside the extension are different origins and always have been. The README's
console snippet is gone, replaced by two buttons.

### Quick categorise — request 2

The category tag on a card is now the control for the thing it names. Click it
and a menu opens at the tag with every category — colour, icon, name — plus
uncategorised, with the current one marked. Pick, and it is filed.

This is mostly for the "+ add" button: a channel added from YouTube arrives with
no category at all, and before this the only way to give it one was to open the
edit pane and use the picker. The menu closes on a pick, a click anywhere else,
a scroll, a resize, or the same tag again — a menu that outlives what it was
anchored to is worse than no menu.

### The + add button moves — request 3

Top centre. YouTube's masthead is the one strip of a channel page that is always
the same, so a button under it is in the same place whatever the page is doing
further down.

### Category icons — request 4

Twenty, plus none. They live in `ext/model.js` as inner SVG markup rather than a
font or a sprite, so there is nothing to load, and they are stroke-only on a
24-unit grid inheriting `currentColor` — which means one icon is the category's
own colour on a card, on a filter chip, and in the quick menu, without any of
them being told which colour.

The picker is a grid that opens under the category's row in the categories pane,
one row at a time: twenty-one buttons is a panel, not a control, and five of
them open at once is the whole sheet. An unknown key draws nothing rather than a
broken glyph, which is what makes the set safe to change later.

### Content width — request 5

A slider in settings, from 880px to "as wide as the window". The board always
reflowed to any width; what it could not do was decline the space. The top of
the range has to mean *off* rather than 2600px, or an ultrawide cannot express
what it wants — so it stores 0 and the label says `full width`.
