## What was done

### The guard redirects — task 7

v0.2.0 covered a blocked page: blur it, put the board over it in an iframe. That
did not work, and on reflection covering was never really blocking — the page
was still loaded, still playing, and one Escape from being underneath you.

A blocked page now **changes address**. The tab goes to
`index.html?blocked=1&from=…`, the YouTube document is gone, and what decides
where you end up next is the board rather than a layer on top of something you
did not choose. `location.replace`, not `href`, so the blocked page does not sit
in the back button waiting to be walked into again.

The blur stays, but only as cover: it hides the page for the few milliseconds
between `document_start` and the decision, so nothing of the feed is ever seen.
The whole overlay — the iframe, the shadow root, its stylesheet, the picker mode
in the board, and the message channel that let it steer the tab — is gone.

The other half of task 7, "every video click that didn't come from a channel
page", changed too. v0.2.0 unveiled a watch page optimistically and checked
afterwards, which let a video of anyone at all run for a second before the guard
caught up. The veil now stays on until the owner has been read. A video reached
from the channel's own page never waits: the click clears it *before* the
navigation, which is what keeps the allowed path instant.

Getting out is now on the board, because the board is where a block lands you:
a sticky bar with **go back anyway**, **pause 15 min** and **turn guard off**.
Each dismisses the tab first — otherwise the guard would send it straight back —
and dismissals live in the worker, keyed by tab and timed at 20 minutes, so they
survive the navigation that follows them. The triple-escape remains for a page
that is somehow still covered.

### Add mode — task 4

A toggle in settings and in the popup. It stands the guard down and grows a
**+ add to hub** button on every channel page, so a channel you have just found
goes onto the board without typing its URL. The button reports back in place —
*added*, or *already on the board* — and matches an existing channel by scope
rather than by string, so the same channel spelled `/@handle` and `/channel/UC…`
is not filed twice.

**This forced the storage change.** The board's channel list lived in
`localStorage`. A content script on youtube.com cannot reach the extension's
`localStorage`, and a service worker does not have one at all. So inside the
extension the three keys now live in `chrome.storage.local`, which every part of
the extension can reach; off disk they stay in `localStorage`.

`js/store.js` became a cache over whichever of the two is there. Every read is
still synchronous — the rest of the app is unchanged by this — and the only new
rule is that the first render waits on `Store.ready`. The store also watches
`chrome.storage`, so a channel added from a YouTube page appears on a board that
is already open, in another tab, without a reload.

`ext/model.js` is new and holds what a channel is, what a category is, and what
the keys are called. Two ends now write channels, so the record shape lives in
one file that both read — the same reason `ext/scope.js` exists.

### Click heat — task 2

Every open is now two facts: when it last happened, which orders "last viewed",
and how often, which is the heat.

- a **most clicked** sort, ties broken by name so the board does not shuffle
  when two channels are level
- a **rule under each card**, coloured by where that channel sits between the
  least and the most opened on the board. It is mixed against the board's own
  maximum, so it only means anything read across all of them — which is the
  point of a heat scale. With nothing clicked yet there is no scale to be on, so
  every line sits at the cold end rather than all of them claiming to be hottest.
- the **two ends of the gradient** are chosen in settings, with the cards
  repainting behind the sheet as they are picked
- the line and the **click counts** are each toggleable; counts are off by
  default, since the number is the less useful half of the same fact

Settings is a new pane, and the first one — the board had none.

### Categories — tasks 1 and 5

- **any colour**: an eleventh swatch is a colour well wearing the same shape as
  the ten presets, so "any colour" is one click deeper rather than somewhere else
- **reorder**: up and down on each row, which moves it in the filter bar and in
  the category sort. Buttons rather than dragging — this is five rows in a sheet,
  and a drag is the thing that goes wrong on a trackpad
- **hide empty**: a settings toggle that keeps categories holding nothing out of
  the filter bar. One that is switched on stays regardless, or turning it off
  again would need a trip to settings

### Three panes, not one box — task 6

The sheets used to be one element whose contents were swapped. Now there are
three — channel, categories, settings — each its own element with its own title
and its own animation. Nothing announced which one you were looking at, and the
box kept the height of whichever had been in it last.

### Room under the delete button — task 3

The sheet's bottom padding was 18px, which put the red delete button hard
against the edge of the pane. The action row is the last thing in every pane, so
the room went there: 28px at the bottom and 14px above the row, which fixes all
three at once.

### Two defects found while building

- **Switching panes left focus in the pane being hidden** — the category name
  field, say — and every keyboard shortcut stands down while you are typing, so
  `/` and `n` were dead until something else was clicked. The same bug the sheet
  *close* had in v0.1.0, in the new code path; `openSheet` now blurs too.
- The click that opens a channel was counted in one place and read in another:
  `touch()` now writes the stamp and the count together, which is what makes
  "most clicked" and "last viewed" agree about what an open is.
