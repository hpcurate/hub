## What was done

### Reading YouTube — the new dependency, and how it is contained

Three of these need something the app has never done: ask YouTube a question.
`ext/yt.js` is the whole of that, and it is pure — string in, object out. It is
the only code in HUB that depends on what YouTube's markup looks like, which
makes it the most likely thing to break and the one thing worth being able to
test off a saved fragment rather than off the live site. Twenty-five checks do.

Everything in it fails to `null` rather than throwing or guessing. A channel
whose id cannot be read simply has no id yet, and is asked again later.

The fetching lives in `js/enrich.js`, on the board page rather than in the
worker: an extension page holds the same host permissions, so it can fetch
directly, and the store is already there. Off disk none of it runs — a `file://`
page cannot fetch youtube.com and never will. That is a real difference between
the two, and the honest one to make.

**Permission added:** `host_permissions: ["*://*.youtube.com/*"]`. Still no
`tabs`.

### Channel avatars, retroactively — Hugo's first request

The channel's own page carries its picture in `og:image` and its UC id in the
canonical link. Both are read in one fetch, for every channel that has neither —
so the ones already on the board are filled in on the first load after updating,
without being asked for.

The pass is serial with a pause between channels. This is someone's own browser
talking to a site they are logged into; a hundred parallel requests is not a
neighbourly way to ask, and nothing here is urgent. Each channel is written the
moment its answer arrives and the board redraws, so avatars arrive one at a time
— which reads as the thing working, where forty appearing at once reads as a
reload. There is a manual **refresh channel info** in settings for when a
picture has gone stale.

An avatar URL can rotate. A broken image is made to read as "no avatar" rather
than as a torn page.

### Knowing when a channel posts — offered idea 1

Each channel's public feed (`/feeds/videos.xml?channel_id=…`, no key, no quota)
gives its newest upload. A card is marked when that upload is newer than the
last time you opened the channel — which needs no new state at all, because both
of those facts were already on the record. Opening it clears the mark by
definition.

This is the one that makes the board better than the feed it replaced: the guard
took away subscriptions, and until now nothing gave it back.

### The queue — offered idea 4

Watch Later lives behind the feed, so the guard effectively removed it. The
**+ queue** button now appears on any video page you are allowed to be on, and
puts the video aside in HUB instead. It carries its own title and channel, so
the queue is readable without going back to YouTube to ask what any of it was.

Opening one grants **that single video**, not its channel: a video you put aside
is a thing you chose, not a door into everything its channel has ever posted.

### Bulk add — offered idea 3

Seeding the board one channel at a time, each on its own page, was the tedious
part. In add mode the subscriptions page now gets **+ add every channel here**,
which collects every channel linked on it, dedupes by scope rather than by
string, skips what is already on the board, and says how many of how many.

### Type-to-open — offered idea 5

Enter in the search box opens the first card. Three letters and you are on the
channel; it is the difference between a board you read and a launcher you use.
It is a setting, off-switch included.

### The add button moved — Hugo's third request

Into the channel page's own action row, beside Subscribe and Join. That row has
been re-spelled several times by YouTube, so six selectors are tried and the
first that is actually present wins.

It is shown floating **immediately** and moved into the row when the row turns
up, rather than waiting for it. Waiting would mean seconds with no button on a
page still building itself, and on a layout that has moved on the row never
arrives at all — a button you cannot find is the same as no button.

### A lot of settings — Hugo's second request

The controls are now a list in `js/app.js` rather than markup. There are enough
of them that writing each one out by hand is how two of them end up behaving
differently, and adding one should be a line.

- **look** — accent colour, content width, corner radius, motion
- **cards** — avatars and their shape, the new dot, description and how many
  lines, category tag, last viewed, click counts, heat line and its gradient
- **board** — hide empty categories, enter opens the first result, open channels
  in a new tab
- **youtube** — add mode, the + queue button, checking for new videos, how often

Four of the dials are tokens the whole stylesheet already draws with — accent is
`--y`, radius is `--r-base`, motion is `--mo`, width is `--app-w` — so setting
them moves the system rather than one rule. The card switches are classes on the
grid, for the same reason.

are tested against markup written from what those pages are known to contain,
which is not the same as testing them against the pages.
