# v0.13.0 — a second board: Instagram

**Project:** hub (hub extension)
**Date:** 2026-09-09

HUB is two boards in one page. A tab strip above the filter chips switches
between **youtube** and **instagram**; each board has its own accounts and its
own categories, and everything else — the card design, the settings, the queue,
the export — is shared.

## The tab

A tab, not a filter. Switching boards clears the things that only meant
something on the old one — a category chip from the other tab would filter every
card away, and a search for a channel name is not a search for an account name —
while the sort survives, because "last viewed" means the same on both. The tab
you left it on is saved and restored.

Each tab carries the count of what is on it and **a dot when that board has
something new**, which is the whole reason the strip earns its place: a board
you are not looking at cannot otherwise tell you anything.

The board's own words move with it. The search box says *search accounts*, the
button says *+ account*, the sort offers *newest post*, and the count line reads
*11 accounts*. A url decides which board a record belongs on, not the tab that
happened to be open: paste a YouTube link while on the Instagram tab and it is
filed as a channel and the board follows it there, rather than silently becoming
an Instagram account that points at YouTube.

Instagram starts with five categories of its own — friends, art, places, food,
follow — because nobody files an Instagram account under "learning". Categories,
the chips, the click-heat scale and the new-count are all per board; a lookup by
id still finds either. An export carries both boards, and a board written before
there were two is read as a YouTube board and has the empty one topped up.

## No guard on Instagram

The YouTube half is unchanged: the board is still the only door into YouTube.
**Instagram is not guarded at all.** instagram.com browses exactly as it did
before HUB was installed — nothing is blocked, blurred or redirected. The
Instagram tab is a board of accounts.

There is a content script on instagram.com, and it is read-only. It contains no
blocking code. It does two things: it reports what is on a profile page, and in
add mode it puts a **+ add to hub** button on a profile so an account you have
just found goes onto the board without typing its url.

## How "what's new" works without a feed

YouTube hands HUB two things for free: a per-channel RSS feed on a plain url
with no key, and a channel page that answers a logged-out fetch. Instagram hands
over neither — there is no per-account feed, and an anonymous profile fetch is
answered with a login wall.

So an Instagram account is checked the way a person would check it: **the page
is opened in a background tab**, in the session already signed in, and the
content script reads the document. Two loads at most, and the second only when
it has earned it:

1. **the profile** — the picture, and the shortcodes across the top of the grid
2. **one post**, only when a shortcode has appeared that this account has never
   shown before, for its real `<time datetime>`

The grid carries no dates, but it does not need to: a shortcode is a stable id,
so "something new" is a code that was not there last time. That also disposes of
**pinned posts** for nothing — a pinned post never leaves the top of the grid,
so its code is always already known and it never reads as new twice.

The second load is what makes the rest of HUB work unchanged. With a real
posted-at time, `latest` on this board means exactly what it means on the other,
so the lit fresh card, the 24-hour window, the **new** chip, newest-first sort
and the latest-post box all work without knowing which site they are looking at.

Everything is best-effort and nothing is allowed to empty the board. A login
wall, a timeout, a tab closed by hand or a post that will not open is a failure:
the account keeps what it had and is asked again next time. When the grid is
read but the post is not, the shortcodes are deliberately *not* recorded, so
that post is still new on the next pass rather than being permanently missed.

**Rate.** Refresh checks the board in front of you and not the other one —
refresh on the YouTube tab quietly opening a dozen Instagram tabs would be a
surprise, and one that appears as tabs in your window is the worst kind. It runs
on the refresh button and on the existing `checkEvery` clock. Instagram gets
**two lanes by default, not five**, on a dial of its own: a YouTube lane is a
few kilobytes of XML, an Instagram lane is a whole page rendering in a real tab,
and two at a time is the shape of somebody browsing. This is still automated
access under Instagram's terms; keeping it slow is what keeps it unremarkable.

## Elsewhere

- **Where a card lands** now has an Instagram answer of its own: posts, reels or
  tagged. A profile is already the grid, so `posts` is the account itself.
- **The latest-post box** links to instagram.com/p/…, and stores the post's
  thumbnail rather than deriving it — Instagram's is a signed CDN link that
  expires, and when it dies the picture leaves the card rather than tearing.
- **The popup** covers both boards: *random* opens either, and open and queue
  send you to the right site. Its heading reads *fresh posts*.
- The offline web app caches `ext/ig.js` with the rest of the shell.

## Tests

732 checks, all passing. `test/ig.mjs` is new — 42 of them — and tests the url
rules and the two page readers against pages built in jsdom rather than against
the live site, which is the same bargain `ext/yt.js` makes. The harness gained
the tab strip, per-board categories and counts, and the whole check-an-account
path with the tab stubbed: that a new shortcode behind a pinned one is still
found, that an unchanged grid costs one load rather than two, that a post which
will not open does not get recorded as seen, and that a login wall never empties
the board.

Not verified by eye: jsdom does not paint, so the tab strip needs looking at,
and nothing here has been run against instagram.com itself — the page readers
are tested against markup written in the test rather than against Instagram's
real pages, so the selectors are the part most likely to need a correction.
