## What was done

### The colour picker bug — request 7

A native colour dialog fires `input` on **every** movement inside it, not once
at the end. The category row's handler called `renderCats()` on the first of
those, which rebuilt the row — including the `<input type="color">` the dialog
belonged to. The element the dialog was attached to stopped existing, so the
dialog shut. That is exactly "pops up and immediately disappears after I click".

The swatch callback now says whether it is a live preview or a commit.
`input` (live) writes the colour and repaints what is already on screen —
the row's own colour variable and the cards behind the sheet — and rebuilds
nothing. `change`, which fires when the dialog closes, does the rebuild.
Clicking one of the ten presets is a commit and still redraws immediately.

The regression test is the honest one: dispatch an `input` and assert the *same
element* is still in the document afterwards.

### The name — request 5

Two things were cutting it. The line box was tighter than the font's descenders
(`line-height: 1.2` on Space Grotesk at 17px), so the tail of a `g` or a `y` on
the last line met the clip edge; and the wrap had no room of its own. It now has
`1.32` leading, two pixels of padding under it, `hyphens`, and a `min-height` of
one line so a short name does not make a shorter card than its neighbours.

How many lines it may take is a setting — one to four, two by default.

**Not verified.** This is a rendering fix and nothing in jsdom lays out or
paints. If it still clips, the next thing to try is the font's own metrics
rather than the box around it.

### Badges — requests 1 and 3

The two hard-coded spans became a list, which is what made five more of them
cost nothing. Each is a row in `BADGES` and a switch in settings:

| | |
| --- | --- |
| last viewed | as before |
| click count | as before |
| **when the channel last posted** | from its feed, so extension only |
| **when you added it** | |
| **its rank on the board by clicks** | `#1`, `#2` … |
| **how many of its videos you have queued** | matched by scope, not by string |
| **its youtube handle** | |

`get` returns the text or `null`, and null is not the same as off: a channel
whose upload date is unknown shows no upload badge whatever the setting says. A
badge that is off is now absent from the card rather than present and hidden —
which is also why the tests stopped asking about a `no-counts` class.

The two board-wide facts — rank, and how many are queued per channel — are
worked out once per render rather than once per card.

### Layout, positioning and presets — requests 2 and 4

Four presets: **classic**, **compact**, **list**, **poster**. A preset is not a
mode. It writes the same dials the rows below it write, and every one of them is
still yours afterwards — which is why nothing is highlighted as "current" and
there is no custom preset. Pretending otherwise would be a lie the settings pane
tells about itself.

Underneath them: card shape (card / compact / list), where the avatar sits (left
/ top), where the badges sit (bottom / top), avatar size, lines for the name,
space between cards, card edge (hairline / none / accent) and card ground
(raised / flat). List is a genuine second shape — one column, the card on its
side — because a board of ninety is a list, not a grid.

### Categorise mode — request 6

Exactly as asked: a **categorise** toggle, a strip to pick one category, then
click through the cards. It starts on whichever category is being filtered for,
if exactly one is, since filtering to a category and then filing into it is the
obvious pass.

While it is on, the board is not a set of links, and it says so loudly — the
strip, an accent edge on hover, a copy cursor, the filter chips dimmed. A mode
you can be in without noticing is a mode that opens YouTube when you meant to
file something. It ends on the toggle, on **done**, or on Escape.

### One defect found while building

`dataset.avatarPos` writes `data-avatar-pos`, not `data-avatarPos`, so the two
stylesheet rules for a top-positioned avatar matched nothing. The test now
asserts the attribute that exists rather than the property that set it, which is
the thing the stylesheet actually depends on.
